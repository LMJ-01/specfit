# 스펙핏 (specfit.kr)

AI·개발 작업용 하드웨어를 **스펙 기준으로 골라주는** 사이트.
GPU, 노트북, 모니터, 메모리를 다룹니다.

- 배포: https://specfit.kr (GitHub Pages)
- 계획·의사결정 기록: [`side-income-plan`](https://github.com/LMJ-01/side-income-plan) 저장소
- **다음에 할 일: [side-income-plan/docs/next-steps.md](https://github.com/LMJ-01/side-income-plan/blob/main/docs/next-steps.md)**

## 시작하기

```bash
npm run build    # 마크다운 → HTML 생성
npm run serve    # 빌드 후 localhost:4173
```

**`npm install` 이 필요 없습니다.** 의존성 0입니다.

`main` 에 푸시하면 GitHub Pages 가 자동 배포합니다. 생성된 HTML 도 커밋합니다.

### ⚠️ 로컬에서 구매 버튼을 누르면 에러가 납니다 — 정상입니다

`localhost` 에서 쿠팡 링크를 누르면 **"사용 권한이 없습니다"** 가 뜹니다.
고장이 아니라 파트너스가 **등록되지 않은 채널**에서의 접근을 막는 것입니다.
등록된 채널은 `specfit.kr` 하나뿐입니다.

링크 확인은 반드시 **배포된 `specfit.kr`** 에서, **한 번만** 하세요.
자가 클릭은 부정행위로 계정 정지 사유입니다.

## 구조

```
src/
  build.js       생성기 — 마크다운을 읽어 HTML·sitemap·검색인덱스 출력
  markdown.js    직접 만든 마크다운 파서 (표·코드·FAQ 지원)
  templates.js   레이아웃 + SEO 메타 + 구조화 데이터
  config.js      사이트 설정 ← 도메인·고지문구·애드센스는 여기만 고치면 됨
  gpu-data.js    계산기 데이터 ← 쿠팡 링크도 여기
  content/
    posts/*.md   글
    pages/*.md   고정 페이지
assets/
  vram-render.js  계산과 화면 만들기 ← 빌드와 브라우저가 함께 씀
  vram.js         마운트·주소·이벤트 (브라우저 전용)
  style.css, search.js
```

루트의 `.html`, `sitemap.xml`, `robots.txt` 는 **생성물**입니다. 직접 고치지 마세요.

## 글 쓰는 법

`src/content/posts/` 에 `.md` 파일을 만듭니다. 파일명이 URL 이 됩니다.

```markdown
---
title: 제목 — 60자 이내 (넘으면 검색결과에서 잘림)
description: 검색 스니펫에 쓰입니다. 160자 이내.
date: 2026-08-14
category: gpu          # gpu / laptop / monitor / memory
tags: [RTX4070, 로컬LLM]
affiliate: false       # 쿠팡 링크를 본문에 넣으면 true
---

본문...

{{VRAM_TOOL}}          ← 이 줄이면 그 자리에 계산기가 들어감

{{COUPANG:rtx4070}}    ← 쿠팡 상품 위젯 (사진 + 실시간 가격)
{{COUPANG:laptop}}     ← GPU 가 아닌 품목도 됩니다 (laptop/monitor/ram/ssd)

## 자주 묻는 질문      ← 이 절의 h3 가 FAQPage 구조화 데이터로 자동 변환됨

### 질문은 h3 로
답변은 그 아래 문단으로 씁니다.
```

이미지에 크기를 주려면: `![설명](/img/a.png =800x450)` → `width`/`height` 가 붙어 CLS 를 막습니다.

들여쓴 다음 줄은 **같은 항목으로 이어집니다.**

```markdown
- **데이지체인** — 첫 모니터에서 두 번째로 잇습니다. **DisplayPort 에만 있고**,
  첫 모니터에 DP 출력 단자가 있어야 합니다
- **USB-C 원케이블** — 노트북이라면 한 가닥으로 끝납니다
```

들여쓰기(공백 2칸)가 있어야 합니다. 없으면 새 문단으로 떨어져 나갑니다.

> 2026-08-18 까지는 이게 안 됐습니다. 둘째 줄이 `</ul>` 다음으로 밀려나
> **목록 밖에 문단으로 떠 있었습니다.** 화면에서는 그럴듯해 보여서 오래 못 찾았습니다.
> 두 줄짜리 항목을 쓸 일이 있으면 빌드 후 실제 HTML 을 한 번 보세요.

### FAQ 답변에 목록을 써도 됩니다

`### 질문` 아래의 문단과 **목록이 모두 답변으로 들어갑니다.**
구조화 데이터에는 마크다운 기호를 뗀 **평문**으로 나갑니다 —
`**강조**` 나 `[링크](/주소)` 를 써도 검색 결과에는 글자만 보입니다.

> 인용(`>`)·표·코드블록은 답변에서 빠집니다. 답이 거기에만 있으면
> 리치 결과에 빈 답변이 나갑니다. **답은 문단이나 목록에 적으세요.**

### 필요 메모리와 판정은 빌드가 대조합니다

글의 `필요 메모리` 표는 전부 계산기와 같은 식에서 나온 값입니다.
`gpu-data.js` 의 `perB` 나 `kvPerK` 를 고치면 글의 표도 함께 고쳐야 하는데,
**이걸 사람이 기억하는 구조였습니다.**

한 번 어긋난 적이 있습니다 — KV 캐시를 파라미터 수에 비례시켜 놓아서
긴 컨텍스트에서 실제보다 최대 5 배 적게 잡았고, 그 값이 글 열 편에 박혀 있었습니다.
**KV 캐시는 파라미터가 아니라 레이어 수를 따라갑니다.** 자세한 건 `gpu-data.js` 주석.

지금은 **빌드가 표를 계산기와 대조합니다.**

```
⚠️  점검 필요 1건
  - rtx4060-local-llm: 판정이 계산기와 다릅니다 — 12~14B @ 8GB:
    글은 "여유", 계산기는 "느림" (q4/medium)
```

표에 적힌 기준(양자화·길이)은 산문에 있어서 기계가 못 읽습니다. 그래서
**표가 스스로 증명하게** 합니다 — 올바른 표라면 모든 행이 같은 기준 하나로 설명돼야
하므로, 행마다 가능한 기준을 구해 교집합을 냅니다. 비면 낡은 표입니다.

**검사되는 표의 모양** (이 형태로 쓰면 자동으로 검사됩니다)

```markdown
| 모델 크기 | 필요 메모리 | 4060 8GB에서 |
|----------|-----------|-------------|
| 12~14B   | 약 10.6GB  | 느림         |
```

- 첫 열이 `모델`·`다루는 길이`·`양자화` 로 시작해야 합니다
- 판정 열 헤더는 용량(`16GB 에서`)이나 카드 이름(`5070 Ti`) 아무거나 됩니다
- `여유 / 빠듯 / 느림 / 불가` 는 계산기 용어입니다. 이 표 안에서 쓰면 대조됩니다

> ⚠️ **검사가 닿지 않는 곳이 있습니다.** `필요한 VRAM`(살 카드 용량)이나
> `| 작업 | 필요 메모리 |`(맥 통합메모리 권장치)는 **다른 값**이라 일부러 뺐습니다.
> 표 밖 산문에 적은 판정도 검사되지 않습니다.
> 그런 자리에 판정 용어를 쓸 때는 **계산기를 직접 돌려보고 쓰세요.**

특히 흔한 조합에서 계산기는 `여유` 에서 **곧바로 `느림` 으로 넘어갑니다.**
`빠듯` 구간은 VRAM 의 10% 폭뿐이라 잘 걸리지 않습니다.
"돌아가긴 하는데 빠듯하다" 는 표현이 쓰고 싶어질 때가 실제로는 `느림` 입니다.

## 빌드가 자동으로 잡아주는 것

`npm run build` 실행 시 경고로 표시됩니다.

- `description` 누락 / 160자 초과
- 제목 60자 초과
- `category` 누락
- **본문에 쿠팡 링크가 있는데 `affiliate: true` 가 없는 경우** ⚠️
- **글의 표가 계산기와 어긋나는 경우** ⚠️ (아래)

마지막 항목이 중요합니다. 공정위 대가성 고지는 **글 첫 부분**에 있어야 하고,
누락이나 하단 표기는 **수익 전액 몰수 + 계정 경고** 사유입니다.

## 자동으로 처리되는 것들

사람이 기억할 필요가 없게 만들어 둔 것들입니다.

| 항목 | 동작 |
|------|------|
| 공정위 고지 | `affiliate: true` 이거나 **계산기·위젯을 실으면** 본문 맨 위에 자동 삽입 |
| 위젯 CLS | iframe 높이만큼 `min-height` 를 미리 잡아 콘텐츠 밀림 방지 |
| 이미지 로딩 | **첫 이미지**만 `fetchpriority="high"`, 나머지는 `loading="lazy"` (LCP 보호) |
| 위젯 오타 | 잘못된 id 는 경고 후 제거 — 페이지에 `{{COUPANG:…}}` 가 노출되지 않음 |
| 위젯 미발급 | `widget` 이 비어 있으면 경고만 하고 조용히 빠짐 — 받아 넣으면 그때 나옵니다 |
| 제휴 링크 rel | 쿠팡 링크에 `sponsored nofollow noopener` 자동 부착 |
| 구조화 데이터 | Article, BreadcrumbList, FAQPage, SoftwareApplication |
| **FAQ 답변 평문화** | 마크다운 기호를 떼고 내보냄 — 검색 결과에 `**` 가 보이지 않음 |
| **작성용 메모 제외** | `<!-- -->` 주석은 HTML·검색 인덱스 **양쪽에서** 빠짐 |
| sitemap.xml | 글 추가 시 자동 갱신 |
| 관련 글 | 같은 카테고리에서 자동 연결 |
| 계산기 JS | **계산기를 쓰는 페이지에만** 로드 (INP 보호) |

## 계산기

**홈 첫 화면에 그대로 실려 있습니다.** 링크로 보내지 않습니다 —
이 사이트에서 남들과 다른 건 도구 하나인데, 버튼 뒤에 숨기면 처음 온 사람은 안 누릅니다.

> ⚠️ **계산기를 싣는 페이지에는 공정위 고지가 함께 붙습니다.**
> `gpu-data.js` 에 쿠팡 링크가 하나라도 있으면 자동으로 따라붙는 구조입니다.
> 홈·글·도구 페이지 전부 같습니다. **이 연결을 끊지 마세요** — 누락은 수익 전액 몰수 사유입니다.

`gpu-data.js` 의 `new: false` 인 카드는 **추천 대상에서 제외**됩니다.
단종된 카드를 "이걸 사세요"라고 권하는 것은 제휴와 무관하게 나쁜 조언이기 때문입니다.
다만 그 카드를 이미 쓰는 사람도 진단은 받아야 하므로 드롭다운에는 남깁니다.

`buy` 가 빈 카드는 구매 버튼이 뜨지 않습니다. 쿠팡에 신품이 없으면 비워두세요.

### 빌드가 미리 그려둡니다 — 파일이 둘로 나뉜 이유

| 파일 | 누가 쓰나 | 무엇이 있나 |
|------|---------|-----------|
| `assets/vram-render.js` | **빌드 + 브라우저** | 계산, HTML 만들기 |
| `assets/vram.js` | 브라우저만 | 마운트 찾기, 주소 읽고 쓰기, 이벤트, 클립보드 |

빌드가 `vram-render.js` 로 **기본 상태를 미리 그려 HTML 에 박아둡니다.**
브라우저도 같은 함수를 쓰므로 결과가 글자 단위로 같고, 그래서 화면이 튀지 않습니다.
주소에 `?gpu=…` 가 붙어 있을 때만 다시 그립니다.

> ⚠️ **`vram-render.js` 에서 `document`·`window`·`location` 을 쓰면 빌드가 깨집니다.**
> 브라우저에만 있는 것은 전부 `vram.js` 로 보내세요.
>
> 그리고 **같은 입력이면 같은 문자열이 나와야 합니다.** 난수나 현재 시각을 넣으면
> 빌드 결과와 브라우저 결과가 갈리고, 첫 렌더에 화면이 튑니다.

2026-08-18 까지는 서버가 빈 `<div data-vram-tool></div>` 만 보냈습니다. 그래서

- **JS 를 안 돌리는 크롤러**(네이버 Yeti 등)에게 이 사이트의 유일한 차별점이 안 보였고
- 나중에 삽입되면서 아래 내용을 밀어냈습니다

`min-height` 로 자리만 잡는 방법도 검토했는데, 컨트롤이 화면 폭에 따라 1~3행으로
접혀서 높이가 **520~810px** 로 벌어집니다. 한 숫자로는 못 맞춥니다 —
과하게 잡으면 첫 화면에 빈 칸이 남습니다. 미리 그리는 쪽이 유일하게 정확합니다.

### 결과를 링크로 공유합니다

선택을 바꾸면 주소에 `?model=…&len=…&gpu=…&quant=…` 가 붙고, 그 주소를 열면 같은 결과가 나옵니다.
**"이 결과 링크 복사" 버튼**이 지금 주소를 클립보드에 넣습니다.

- 해시(`#`)가 아니라 쿼리(`?`)를 씁니다 — 계산기 페이지의 본문 앵커와 부딪히지 않게 하기 위해서입니다
- `replaceState` 라 뒤로가기 기록이 쌓이지 않습니다
- 목록에 없는 값이 들어오면 조용히 기본값으로 돌아갑니다 (낡은 링크 대비)
- 예전 `?use=coding` 형태의 링크도 모델 크기로 옮겨 받습니다
- 색인에는 영향이 없습니다. 모든 페이지에 canonical 이 박혀 있습니다

계산기는 글 본문에도 실리므로, **글 URL 에 파라미터가 붙은 형태로도 공유됩니다.**

## 콘텐츠 원칙

- **스펙으로 판단할 수 있는 것만** 다룹니다.
  키보드·의자처럼 써봐야 아는 제품은 제외합니다

  "스펙 기준으로 선별했다"고 밝히는 편이 오히려 신뢰를 얻습니다
- `og:image` 는 **PNG/JPG** 만. WebP 는 카카오톡 크롤러가 못 읽어 공유 카드가 빕니다

### 작성용 메모는 `<!-- -->` 안에

수치 출처·확인 날짜·"이건 넣지 마세요" 같은 메모는 글 맨 위 주석에 적습니다.
**HTML 에도, 검색 인덱스에도 나가지 않습니다.**

> ⚠️ 2026-08-18 까지는 **검색 인덱스로 새고 있었습니다.**
> 인덱스가 원문 앞 600자를 자르는데 그 앞부분이 통째로 메모라,
> 42편 전부 "직접 측정한 값이 아닙니다" 같은 내부 메모가 공개 JSON 에 실리고
> **정작 본문은 색인되지 않았습니다.** 지금은 주석을 먼저 걷어냅니다.
>

## `.nojekyll` 이 왜 있나

GitHub Pages 는 기본으로 Jekyll 빌드를 돌립니다. 이 사이트는 **이미 HTML 로 만들어
커밋하는 구조**라 Jekyll 이 할 일이 없는데, 그냥 두면 위험이 하나 있습니다.

`src/content/posts/*.md` 에 `{{VRAM_TOOL}}`, `{{BUY:ssd}}` 같은 자리표시자가 들어 있습니다.
**Jekyll 의 Liquid 문법과 모양이 같습니다.** Jekyll 이 이걸 변수나 태그로 해석하려다
실패하면 **배포가 조용히 멈춥니다** — 푸시는 성공했는데 사이트만 옛 상태로 남습니다.

`.nojekyll` 은 "그대로 서빙하라" 는 표시입니다. 파일이 비어 있는 것이 정상입니다.
