노트북은 데스크톱과 고르는 방식이 다릅니다.

**부품 대부분을 나중에 못 바꾸기 때문**입니다.
그래서 "지금 필요한 것"이 아니라 **"바꿀 수 없는 것"**부터 정해야 합니다.

## 결론부터 — 순서가 중요합니다

| 순위 | 항목 | 나중에 바꿀 수 있나 |
|-----|------|------------------|
| 1 | **램** | 대개 못 바꿉니다 |
| 2 | **화면** | 못 바꿉니다 |
| 3 | **그래픽카드** | 못 바꿉니다 |
| 4 | SSD | **바꿀 수 있는 경우가 많습니다** |
| 5 | CPU | 못 바꾸지만 대개 충분합니다 |

**SSD만 나중에 해결됩니다.** 나머지는 살 때 정해집니다.
그러니 예산이 빠듯하면 **SSD를 가장 작게 잡고 나머지에 쓰는 편**이 낫습니다.

## 1. 램 — 슬롯이 있는지부터 확인

**최근 얇은 노트북은 램이 메인보드에 납땜되어 있습니다.**
LPDDR 계열을 쓰는 모델이 특히 그렇습니다.

사기 전에 확인할 것:

- 제품 사양에 **"온보드"** 또는 **"교체 불가"** 표기가 있는지
- 램 슬롯 개수가 명시되어 있는지
- 분해 후기에서 슬롯이 보이는지

**슬롯이 없다면 살 때 32GB를 골라야 합니다.**

### 몇 GB를 골라야 하나

| 작업 | 권장 |
|------|------|
| 웹 개발, 가벼운 작업 | 16GB |
| 도커·가상머신·에뮬레이터 | **32GB** |
| 로컬 LLM을 CPU로 | 32GB 이상 |

**도커나 안드로이드 에뮬레이터를 쓴다면 16GB는 좁습니다.**
자세한 기준은 [램 16GB vs 32GB](/posts/ram-16gb-vs-32gb.html)에 정리했습니다.

## 2. 화면 — 해상도와 크기

노트북은 모니터를 나중에 붙일 수 있지만, **들고 다닐 때는 내장 화면이 전부**입니다.

PPI를 계산하면 이렇습니다.

```
PPI = 대각선 픽셀 수 ÷ 화면 인치
```

| 크기·해상도 | PPI | 코딩에서 |
|-----------|-----|---------|
| 15.6" FHD (1920×1080) | 141 | 무난합니다 |
| 14" FHD+ (1920×1200) | 162 | 세로가 조금 더 깁니다 |
| 16" WQXGA (2560×1600) | 189 | 선명하고 넓습니다 |
| 14" 2.8K (2880×1800) | 243 | 매우 선명, 배율 필수 |

**세로 픽셀이 코딩에서는 중요합니다.**
`1920×1200` 이 `1920×1080` 보다 코드가 한 화면에 더 들어갑니다.
16:10 비율을 쓰는 모델을 눈여겨보세요.

⚠️ **PPI 가 높다고 넓은 게 아닙니다.** 작은 화면에 픽셀이 촘촘하면 배율을 올리게 되고,
올린 만큼 작업 영역이 도로 줄어듭니다. 몇 인치를 골라야 하는지는
[개발용 노트북 몇 인치](/posts/laptop-screen-size.html)에 줄 수로 계산해 뒀습니다.

배율과 작업 영역의 관계는
[코딩용 모니터 글](/posts/coding-monitor-resolution.html)에 자세히 적었습니다.

## 3. 그래픽카드 — 로컬 LLM을 할 거라면

클로드 코드·커서 같은 **클라우드 AI 코딩 도구가 목적이라면 그래픽카드는
필요 없습니다** — 연산이 서버에서 됩니다.
[AI 코딩 도구와 사양](/posts/ai-coding-tool-pc-spec.html)에 공식 요구 사양과 함께
정리했습니다. 그래픽카드가 문제 되는 건 **모델을 직접 돌리는 로컬 LLM**뿐입니다.

**노트북 그래픽카드는 같은 이름이라도 데스크톱과 다릅니다.**

두 가지를 확인하세요.

**VRAM 용량**
이름이 같아도 노트북 쪽이 적은 경우가 있습니다.
[로컬 LLM에서는 VRAM이 먼저](/posts/ollama-minimum-spec.html)이므로 이게 가장 중요합니다.

**전력 제한**
같은 카드라도 노트북마다 허용 전력이 다릅니다.
얇은 모델일수록 낮게 잡혀 성능이 떨어집니다.
제품 사양에 최대 전력이 표기되어 있으면 확인하세요.

### 로컬 LLM 기준 최소선

| VRAM | 할 수 있는 것 |
|------|-------------|
| 6GB 이하 | 3B 정도. 아쉽습니다 |
| **8GB** | 7~8B. 실질적 하한선 |
| 12GB 이상 | 12~14B. 코딩 보조가 됩니다 |

{{VRAM_TOOL}}

내장그래픽만 있는 모델은 로컬 LLM에 적합하지 않습니다.
이유는 [CPU로 돌리면 얼마나 느린가](/posts/local-llm-without-gpu.html)에 있습니다.

## 4. SSD — 여기서 아끼세요

**대부분의 노트북은 SSD를 교체하거나 추가할 수 있습니다.**

슬롯이 두 개인 모델이면 나중에 하나 더 꽂으면 됩니다.
하나뿐이어도 더 큰 것으로 갈아끼울 수 있습니다.

**그러니 살 때 512GB로 시작해도 됩니다.**
그 차액을 램이나 화면에 쓰는 편이 낫습니다.

다만 로컬 LLM을 할 계획이라면 **용량이 생각보다 빨리 찹니다.**
모델 하나가 5~20GB이고, 이것저것 받다 보면 금방 수십 GB가 됩니다.

{{BUY:ssd}}

## 5. CPU — 대개 신경 안 써도 됩니다

**요즘 노트북 CPU는 개발 작업에 대체로 충분합니다.**

- 컴파일이 잦다면 코어 수가 도움이 됩니다
- 로컬 LLM에서는 **CPU보다 그래픽카드**가 훨씬 중요합니다
- 배터리를 중시하면 저전력 계열이 유리합니다

**예산을 CPU 등급에 올리기보다 램이나 화면에 쓰는 편**이 체감이 큽니다.

## 자주 봐야 할 함정

**같은 모델명, 다른 구성**
노트북은 같은 이름 안에서 램·SSD·GPU가 갈립니다.
**상세 구성을 반드시 확인하세요.** 리뷰에서 본 성능과 다른 물건일 수 있습니다.

**"최대 32GB 지원"**
지금 32GB가 들어있다는 뜻이 아닙니다. 슬롯이 받는 최대치입니다.

**노트북 GPU 이름**
데스크톱과 같은 이름이어도 다른 물건입니다. VRAM을 직접 확인하세요.

## 자주 묻는 질문

### 로컬 LLM용으로 노트북이 괜찮나요

가능하지만 데스크톱보다 불리합니다. VRAM이 적고 전력 제한이 있으며
발열로 속도가 떨어질 수 있습니다. **들고 다녀야 하는 게 아니라면 데스크톱**이 낫습니다.

### 맥북과 윈도우 노트북 중에서는

로컬 LLM만 놓고 보면 **큰 모델을 원하면 맥, 속도를 원하면 윈도우 + 전용 GPU**입니다.
맥은 통합 메모리라 128GB까지 가고, 윈도우 노트북은 대역폭이 높은 편입니다.

### 램 16GB인데 32GB로 늘릴 수 있나요

슬롯이 있으면 가능합니다. 제품 사양이나 분해 후기에서 확인하세요.
**온보드면 불가능합니다.**

### 화면은 나중에 모니터를 붙이면 되지 않나요

책상에서만 쓴다면 맞습니다. 다만 들고 다닐 때는 내장 화면이 전부입니다.
**주로 어디서 쓸지**를 먼저 정하시면 답이 나옵니다.

### 게이밍 노트북이 개발에도 좋나요

그래픽카드와 램 슬롯이 있어 로컬 LLM에는 유리합니다.
대신 무겁고 배터리가 짧습니다. **들고 다니는 빈도**가 판단 기준입니다.
유리한 것과 대가를 따로 갈라 [게이밍 노트북 개발용으로 괜찮나](/posts/gaming-laptop-for-dev.html)에 정리했습니다.

### 웹 개발만 하는데도 이 순서대로 봐야 하나요

순서는 같지만 기준이 낮아집니다. 웹 개발은 요구가 낮은 편이라 램 16GB로 대체로 됩니다.
[웹 개발용 노트북 사양](/posts/web-dev-laptop-spec.html)에 따로 적었습니다.

### 배터리는 안 봐도 되나요

우선순위 1번은 아닙니다. 다만 표기 시간이 개발 부하와 안 맞아서 계산이 따로 필요합니다.
[개발용 노트북 배터리](/posts/laptop-battery-dev.html)에 뽑는 법을 적었습니다.

## 정리

1. **바꿀 수 없는 것부터** 고르세요. 램 → 화면 → 그래픽카드 순입니다
2. **램 슬롯이 있는지 확인하세요.** 없으면 살 때 32GB여야 합니다
3. 코딩에는 **세로 픽셀**이 중요합니다. 16:10 비율을 보세요
4. **SSD는 나중에 바꿀 수 있으니** 여기서 아끼세요
5. 노트북 GPU는 이름이 같아도 다릅니다. **VRAM을 직접 확인**하세요
