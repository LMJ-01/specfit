안드로이드 개발용 노트북을 고를 때 "IDE 돌리는 거니까 적당하면 되겠지" 하면 곤란해집니다.

**안드로이드 스튜디오 자체는 그렇게 무겁지 않습니다. 문제는 에뮬레이터입니다.**

에뮬레이터는 **가상의 안드로이드 폰을 통째로 하나 띄우는 것**입니다. 앱 하나가 아니라 기기 한 대가 컴퓨터 안에서 돌아갑니다.

## 결론부터

| 작업 방식 | 필요한 램 |
|----------|---------|
| 실기기만 연결해서 개발 | **16GB로 됩니다** |
| 에뮬레이터 1대 + IDE | **16GB는 빠듯합니다** |
| 에뮬레이터 1대 + IDE + 브라우저 | **32GB** |
| 에뮬레이터 여러 대 (화면 크기별 테스트) | **32GB 이상** |

| 항목 | 판단 |
|------|------|
| **램** | **여기가 전부입니다** |
| CPU | 코어 수가 빌드 시간에 영향을 줍니다 |
| SSD | 512GB는 빠듯합니다. **1TB 권장** |
| 그래픽카드 | 전용 카드는 필요 없습니다 |
| 화면 | **세로 픽셀**이 중요합니다 |

## 1. 에뮬레이터가 램을 먹는 구조

**에뮬레이터는 프로그램이 아니라 기기입니다.**

가상의 폰 한 대를 만드는 것이라, 그 폰이 쓸 램을 컴퓨터에서 떼어줘야 합니다.

```
내 컴퓨터
 └ 안드로이드 스튜디오        1.5~3GB
 └ 에뮬레이터 (가상 폰 한 대)   2~4GB   ← 통째로 예약됩니다
 └ 그레이들 빌드                1~2GB
```

**AVD를 만들 때 램 크기를 정하는데, 그만큼이 실제로 빠져나갑니다.** 기본값이 2GB 안팎이고, 화면이 큰 태블릿 프로필은 더 잡습니다.

### 16GB가 터지는 지점

실제로 이렇게 쌓입니다.

```
윈도우 자체                    4~6GB
안드로이드 스튜디오             1.5~3GB
에뮬레이터 1대                 2~4GB
그레이들 빌드 (빌드 중)          1~2GB
브라우저 (문서·스택오버플로)      1~3GB
──────────────────────────────────
합계                        9.5~18GB
```

**16GB에서는 빌드하는 순간 아슬아슬해집니다.**

증상이 이렇습니다.

- 빌드를 걸면 에뮬레이터가 멈칫합니다
- IDE가 "메모리 부족" 경고를 띄웁니다
- 에뮬레이터가 갑자기 죽습니다
- 디스크가 계속 돌아갑니다 (스왑)

**에러가 명확히 안 나고 전체가 느려지는 것**이라 원인을 찾기 어렵습니다. 램 부족의 전형적인 양상입니다.

내 램이 실제로 부족한지 확인하는 법은
[램 16GB vs 32GB](/posts/ram-16gb-vs-32gb.html)에 있습니다.

## 2. 16GB로 버티는 법

램을 못 늘리는 상황이라면 이 정도가 할 수 있는 전부입니다.

**① 실기기를 쓰세요 — 이게 가장 큽니다**

안 쓰는 안드로이드 폰이 있다면 USB로 연결해서 개발하면 됩니다.
**에뮬레이터를 안 띄우면 2~4GB가 통째로 남습니다.**

게다가 실기기가 더 정확합니다. 카메라·센서·성능이 실제와 같으니까요.

**② AVD 램을 줄이세요**

AVD 설정에서 램 크기를 조절할 수 있습니다. 기본값보다 낮춰도 간단한 앱은 돕니다.
다만 너무 줄이면 에뮬레이터가 느려지거나 죽습니다.

**③ 에뮬레이터는 하나만**

화면 크기별로 여러 대를 띄우고 싶어지는데, 16GB에서는 하나씩 돌리세요.

**④ 그레이들 데몬 메모리 제한**

`gradle.properties`에서 빌드에 쓸 메모리 상한을 정할 수 있습니다.
너무 낮추면 빌드가 느려지니 조금씩 조절하세요.

**⑤ 브라우저 탭을 줄이세요**

의외로 여기서 몇 GB가 나옵니다.

## 3. CPU — 빌드 시간에만 영향을 줍니다

**안드로이드 빌드는 코어를 여럿 씁니다.** 그래서 도커나 웹 개발과 달리, CPU가 실제로 체감되는 영역이 있습니다.

| 작업 | CPU 영향 |
|------|---------|
| 그레이들 빌드 | **코어 수가 도움이 됩니다** |
| 에뮬레이터 실행 | 조금 |
| 코드 편집·인덱싱 | 거의 없음 |

**다만 우선순위는 여전히 램입니다.** 램이 모자라 스왑이 걸리면 CPU가 아무리 좋아도 느립니다.

```
램 부족  →  CPU 가 좋아도 느림
램 충분  →  그때부터 CPU 코어 수가 빌드 시간을 줄임
```

**예산이 있으면 CPU 등급을 올리기보다 램 32GB로 가세요.**
5·7·9 중 어느 것을 살지는 [개발용 노트북 CPU 등급](/posts/dev-laptop-cpu.html)에 정리했습니다.

## 4. 전용 그래픽카드는 필요 없습니다

**에뮬레이터가 GPU를 쓰긴 하지만, 내장 그래픽으로 충분합니다.**

게임을 만드는 게 아니라면 전용 카드에 돈을 쓸 이유가 없습니다. 그 돈을 **램이나 화면**에 쓰는 편이 체감이 큽니다.

> **로컬 LLM을 겸하실 거라면 이야기가 다릅니다.**
> 그건 VRAM이 필요해서 전용 카드가 있어야 합니다 —
> [로컬 LLM 되는 노트북 고르기](/posts/local-llm-laptop-choose.html)를 보세요.

## 5. 화면 — 세로가 중요합니다

안드로이드 스튜디오는 **화면을 많이 씁니다.** 왼쪽에 프로젝트 트리, 가운데 코드, 오른쪽에 미리보기, 아래에 로그캣.

여기에 **에뮬레이터 창까지 띄워야 합니다.**

| 화면 | 안드로이드 스튜디오에서 |
|------|---------------------|
| 15.6" FHD (1920×1080) | 좁습니다. 창을 계속 접었다 폈다 하게 됩니다 |
| 16" WQXGA (2560×1600) | **여유롭습니다** |
| 14" FHD+ (1920×1200) | 세로가 조금 더 나아 도움이 됩니다 |

**16:10 비율이 유리합니다.** 세로 픽셀이 더 많아 로그캣을 띄워도 코드가 남습니다.

외부 모니터를 붙이신다면 [듀얼 모니터](/posts/dual-monitor-vs-single.html)나
[세로 모니터](/posts/vertical-monitor-coding.html)가 도움이 됩니다.
**로그캣은 세로 화면에 띄우기 좋은 대표적인 것**입니다.

## 6. SSD — 생각보다 빨리 찹니다

안드로이드 개발은 용량을 꽤 먹습니다.

| 항목 | 대략 |
|------|-----|
| 안드로이드 스튜디오 | 3~5GB |
| SDK (여러 API 레벨) | **10~30GB** |
| 에뮬레이터 이미지 (1개당) | 5~10GB |
| 그레이들 캐시 | 몇 GB, 계속 쌓입니다 |
| 프로젝트별 빌드 산출물 | 프로젝트당 수백 MB~ |

**512GB로 시작하면 금방 답답해집니다.** 에뮬레이터 이미지를 두세 개만 받아도 20~30GB입니다.

**1TB를 권합니다.** 노트북은 [SSD를 나중에 바꿀 수 있으니](/posts/laptop-ssd-upgrade.html) 당장은 512GB로 시작해도 되지만, 슬롯이 있는지는 확인하세요.

## 7. 맥은 어떤가

**애플 실리콘 맥에서 안드로이드 개발은 잘 됩니다.**

에뮬레이터도 ARM 이미지를 쓰면 원활합니다. 맥의 칩이 ARM이라 **변환 없이 그대로 도는 구조**이기 때문입니다.

다만 **맥은 램을 나중에 못 늘립니다.** 살 때 정해야 합니다.

| 작업 | 최소 |
|------|-----|
| 실기기 위주 | 16GB |
| **에뮬레이터 상시** | **24GB 이상** |

기준은 [맥북 에어 vs 프로](/posts/macbook-air-vs-pro-dev.html)에 정리했습니다.

## 8. 그래서 어떤 노트북을 사야 하나

| 우선순위 | 확인 |
|---------|------|
| 1 | **램 32GB** 또는 **슬롯이 있는 16GB** |
| 2 | 화면 — 16:10 비율, 세로 1200 이상 |
| 3 | SSD 1TB 또는 슬롯 2개 |
| 4 | CPU — 코어 수가 빌드에 도움 |
| — | 전용 그래픽카드는 불필요 |

**램 슬롯이 있는지가 지금 특히 중요합니다.** 2026년 들어 램 값이 크게 올라서, 32GB 구성의 웃돈이 예전보다 큽니다. 슬롯이 있으면 16GB로 시작해 나중에 늘릴 수 있습니다 —
[램 값이 올랐습니다](/posts/ram-price-2026.html)를 참고하세요.

## 자주 묻는 질문

### 에뮬레이터 없이 개발할 수 있나요

**실기기를 USB로 연결하면 됩니다.** 오히려 이쪽이 정확하고 가볍습니다.
안 쓰는 폰이 있다면 개발자 옵션에서 USB 디버깅을 켜고 연결하세요.

### 에뮬레이터가 너무 느립니다

램 부족이거나 하드웨어 가속이 꺼져 있을 수 있습니다.
윈도우에서는 가상화 기능이 켜져 있어야 합니다 — BIOS 설정과 윈도우 기능을 확인해 보세요.

### 16GB인데 32GB로 늘리면 확실히 나아지나요

**에뮬레이터를 쓰신다면 네.** 지금 스왑이 일어나고 있을 가능성이 큽니다.
작업 관리자에서 **"커밋된 메모리"가 물리 램보다 크면** 이미 디스크로 넘어가고 있다는 뜻입니다.

### 게이밍 노트북이 나은가요

램 슬롯이 있고 냉각이 좋아 유리한 면이 있습니다.
다만 무겁고 배터리가 짧습니다. **들고 다니는 빈도**로 판단하세요.
판단표는 [게이밍 노트북 개발용으로 괜찮나](/posts/gaming-laptop-for-dev.html)에 있습니다.

### 에뮬레이터를 오래 켜두면 전체가 굼떠집니다

램 부족일 수도 있고 발열일 수도 있습니다. 에뮬레이터는 상시로 부하가 걸리는 작업이라
얇은 노트북에서는 열이 쌓입니다. 구분하는 법은
[노트북 발열과 성능 저하](/posts/laptop-thermal-throttling.html)에 적었습니다.

### 도커도 같이 쓰는데요

그러면 32GB는 사실상 필수입니다. 에뮬레이터와 도커가 각각 램을 통째로 예약합니다.
[도커 노트북 사양](/posts/docker-laptop-spec.html)에 그쪽 기준을 적었습니다.

### 로컬 LLM도 같이 할 수 있나요

됩니다. 다만 **로컬 LLM은 VRAM, 에뮬레이터는 시스템 램**으로 서로 다른 자원을 씁니다.
둘 다 하시려면 램 32GB + VRAM 12GB 이상이 편합니다.

## 정리

1. **IDE가 아니라 에뮬레이터가 문제**입니다. 가상 기기 한 대를 띄우는 것입니다
2. 에뮬레이터를 상시로 쓰면 **32GB**입니다. 실기기만 쓰면 16GB로 됩니다
3. **실기기 연결이 가장 확실한 절약**입니다. 2~4GB가 통째로 남습니다
4. CPU는 **빌드 시간에만** 영향을 줍니다. 램이 먼저입니다
5. **전용 그래픽카드는 필요 없습니다.** 그 돈을 램이나 화면에 쓰세요
6. SDK와 에뮬레이터 이미지가 커서 **SSD 1TB**를 권합니다

실제 사용 결과가 다르면 [알려주세요](/contact.html). 확인 후 갱신합니다.
